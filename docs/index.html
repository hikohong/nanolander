nanolander

Land on any machine with your whole kit

One script that installs the same modern terminal toolkit on macOS, Ubuntu, Amazon Linux 2, and Amazon Linux 2023, then wires up your shell. Packages come from the system repository when available, and from official GitHub releases when not.

Getting started

Download and run it. The script detects the platform and CPU architecture on its own.

# install everything
$ git clone https://github.com/hikohong/nanolander.git
$ cd nanolander
$ ./bin/nanolander

# load the new settings (the run prints which file it wrote)
$ source ~/.bashrc

The package manager comes from the platform, but the shell file comes from your login shell — that is what decides which file is ever read. bash gets ~/.bashrc, zsh gets ~/.zshrc, and a wrapper counts: an Amazon cloud desktop logs you into logbash, which is bash. Options

All of them combine, for example --set-default-shell --with-aliases --configure-git.

--list-tools

Print every tool the script can install, with its purpose, so you can see the list before filtering.

./bin/nanolander --list-tools
--only a,b,c

Install just these tools; everything else is marked SKIPPED. Useful for topping up a few tools, or for machines with limited network access. Match by command name or tool name.

./bin/nanolander --only nvim,tmux,fzf,ripgrep
--skip a,b,c

Install everything except these. Machines without Docker can drop lazydocker and dive.

./bin/nanolander --skip lazydocker,dive
--shell bash|zsh

Configure that shell rather than the one detected from your login shell. Use it when you log in as one shell and want the other set up, or run the script twice to configure both. Without it the target is decided strongest-first: --shell, then --set-default-shell, then your login shell, then the platform default.

./bin/nanolander --shell zsh
--set-default-shell

On macOS and Amazon Linux, change the login shell to zsh. It does nothing if zsh is already the login shell, and Ubuntu keeps its bash setup. Because it makes zsh your login shell, the run targets ~/.zshrc too — so --shell bash alongside it is refused as a contradiction.

--with-aliases

Add an optional alias block: ls ll lt to eza, cat to bat, du to dust, df to duf, top to btm. Every line checks that the tool exists first, and the block is fenced with start and end markers so you can remove it in one go.

--configure-git

Set git-delta as the global Git pager, so git diff, git log, and git show get syntax highlighting and line numbers, and switch merge conflicts to zdiff3. Skipped with a warning if git or delta is missing.

--without-nvim-config

The Neovim configuration is installed by default, by handing off to ./bin/nvim-land --apply once the tools are in. This flag opts out and leaves ~/.config/nvim alone; so does filtering Neovim out with --only or --skip. --with-nvim-config is still accepted and now does nothing. Skipped with a warning when Neovim is missing, or when the helper is not beside this script.

./bin/nanolander --without-nvim-config
--restore-shell

Put your shell config file back the way it was. Every run copies ~/.zshrc, ~/.bashrc and ~/.zprofile into ~/.nanolander-backups the first time it is about to write to them, and this restores the most recent copy. The version being replaced is kept too, so the restore is itself undoable.

./bin/nanolander --restore-shell
--uninstall

Back the changes out instead of rolling the file back: remove only the lines nanolander added, plus the tools it recorded under ~/.local. Anything you wrote yourself is untouched, and packages installed through brew, apt, dnf, or yum are left alone.

./bin/nanolander --uninstall
--help

Show usage and examples without installing anything.

Neovim config

The main script installs Neovim and this configuration with it. bin/nvim-land is that step on its own — how you inspect it, redo it, or undo it. Opt out with --without-nvim-config.

# look first
$ ./bin/nvim-land
# back up ~/.config/nvim, then install
$ ./bin/nvim-land --apply
# put the previous tree back
$ ./bin/nvim-land --restore

The files ship in share/nvim and are copied to ~/.config/nvim. Only files nanolander ships are written; anything else you keep there is reported and left alone.

Copilot's inline suggestion is here too — <C-l> accepts it — but it is the one entry that cannot simply land: it needs Node, a subscription and :Copilot auth once per machine, so only its automatic trigger is gated and a box with no credentials never loads it at all.

Worth knowing

  • Neovim removed cscope — has('cscope') is 0, so the cscope block in ~/.vimrc never runs there. The keys above are the replacement; for real cscope, use vim.
  • A language server beats cscope and ctags both, and nanolander does not install one. clangd is the one worth having for C and C++; ./bin/nvim-land reports which servers the machine can already run.
  • Parsers need the tree-sitter CLI and a C compiler — Neovim ships parsers for c, lua, markdown, query, vim, and vimdoc, so C works out of the box; anything else compiles on first start.
  • Treesitter highlighting is not pixel-identical to vim, because it paints with @capture groups rather than the ones a hand-tuned colourscheme targets. One flag at the top of plugins.lua keeps treesitter for folds only.
  • ,sp and ,lp write session.nvim and shada.nvim — Neovim's info file is msgpack shada and vim's is text, so sharing one pair would leave whichever editor wrote last unreadable to the other.

How it works

Every tool goes through the same path, and the summary records where each one came from.

Environment detection

Reads uname -s and /etc/os-release to pick the package manager and shell target, then normalises uname -m into x86_64, arm64, armv7, or armv6 to choose the right release asset later.

wants_tool

Handles --only and --skip. Matching ignores case and spacing and accepts either the command or the tool name. Filtered tools are reported as SKIPPED and never count as failures.

setup_homebrew

macOS only. If brew is missing, it downloads the official installer, runs it non-interactively, and loads the matching brew shellenv.

The install_package family

Wraps "is it in the repo", "is it already installed", and "install it" behind one interface, switching between apt-cache, dpkg-query, rpm, and brew underneath. try_package_candidates then walks the per-distro naming differences, such as fd-find versus fd, or tlrc versus tldr.

github_install

The fallback for tools no repository carries: look up the latest release, match the asset for this architecture, verify the SHA-256 when GitHub publishes one, extract, and install into ~/.local/bin. Asset matching prefers an exact suffix before falling back to a substring, so linux_arm never picks linux_arm64. Projects that name the binary differently inside the archive (yq) are renamed on the way in, bare executables (shfmt, direnv) skip extraction entirely, and Neovim keeps its full runtime tree behind a symlink. Set GITHUB_TOKEN to raise the API quota.

github_asset_name

Two projects publish more than one build per architecture, and keyword matching picks the wrong one for both, so their asset is named outright. yazi ships a gnu and a musl build of each target: the gnu one wants a newer glibc than Amazon Linux 2 has, so it installs and then cannot run. FFmpeg ships every target as -gpl and -gpl-shared, and containment finds the shared one first because it sorts earlier — its ffmpeg needs the archive's lib directory, which the install throws away. An upstream rename falls back to matching with a warning rather than failing.

github_extras

Some archives carry a second binary that is not optional. yazi ships ya, which is what runs ya pkg for plugins; FFmpeg ships ffprobe, which is the half yazi calls to read a video's dimensions. Both install alongside the catalog command and are recorded for --uninstall. A missing extra is a warning, not a failure.

tool_unsupported_here / ensure_tool

The catalog is the same on all four platforms with three exceptions known in advance. Neovide is a GUI client and resvg has one Linux target, so upstream builds both for macOS and x86_64 Linux only; yazi has no 32-bit ARM build anywhere. None of the three is in the Debian, Ubuntu, or Amazon Linux repositories either, so where there is genuinely nothing to fetch it is recorded as SKIPPED with the reason platform instead of being counted as a failure. Two more gaps can only be found by trying — a build that needs a newer glibc than the system has, and a tool neither the distribution nor upstream packages — and both end in the same row.

make_compat_links

Ubuntu and Debian ship these binaries as fdfind and batcat, the older p7zip packages call 7-Zip 7z rather than 7zz, and ImageMagick 6 has convert but no magick. The script links all four to the names everything else expects and keeps usage identical everywhere.

command_works

Presence is not enough: each tool has to answer a version query (-V for tmux, -v for unzip and pdftoppm, -version for ffmpeg, --version for the rest; entr and 7-Zip have no version flag, so presence on PATH is the check) before it is recorded as successful.

Good to know

  • sudo — installing system packages on Linux may prompt for a password; the script validates sudo access up front.
  • GitHub API limits — unauthenticated quota is low, so a full run can hit a 403. Export GITHUB_TOKEN before running to avoid it.
  • Docker tools — lazydocker and dive need a working Docker environment to be useful; otherwise run with --skip lazydocker,dive.
  • Repository-only tools — tig, cscope, entr, and ctags publish no cross-platform binaries, so they depend on the distro repository. Amazon Linux 2023 ships without EPEL, so entr and ncdu are not packaged there at all and come back as SKIPPED (platform): nothing was attempted, and no re-run changes that. Enable EPEL if you want them.
  • glibc too old for the upstream build — Amazon Linux 2023 is on glibc 2.34, and tree-sitter, resvg, and Neovide publish Linux binaries wanting 2.39 or 2.35. They install fine and then the loader refuses them, so they are reported SKIPPED (platform) with the glibc version named, and the unusable binary is removed rather than left on PATH. Where a static musl build exists it is pinned instead, which is why yazi and gping do work there.
  • Amazon Linux 2 — the repositories are old, so most modern tools arrive from GitHub releases in ~/.local/bin. That is expected.
  • armv6 — official release coverage is thin; tools without a matching build are reported as FAILED, so pair it with --only.
  • Neovide on a server — it is a GUI client and needs a desktop, so on a headless box there is nothing to display; --skip neovide keeps the summary tidy.
  • yazi shows boxes, not a picture — the backends are installed but the terminal cannot draw an image. yazi uses the Kitty graphics protocol, iTerm2 inline images, or sixel; all three are escape sequences and so do travel over SSH, but it is the terminal on your own laptop that has to support them. Inside tmux add set -g allow-passthrough on. Ueberzug is the one adapter that cannot work remotely, because it needs a local display. yazi --debug reports what was detected.
  • A dot completes nothing — self. in Python, -> in C. That asks what an object has, and only a language server can answer it; the path and buffer sources cannot, so the menu stays empty there even though it works fine while you type a word. nanolander installs no language servers, so a freshly landed box has none — ./bin/nvim-land lists the nine it knows and says which are on PATH. Python has four of them and they answer for the same files, so the first one found wins and the report says which, rather than letting two attach and double every candidate.
  • Boxes where the prompt and the file tree should have icons — the font is installed and even selected, and on iTerm2 a second setting still overrides it. Settings → Profiles → Text has Use a different font for non-ASCII text, and while that is on it applies to every non-ASCII character, not only the ones the main font cannot draw — so a profile still naming the old PowerlineSymbols, which predates Nerd Fonts and holds about ten glyphs, shows a box for every icon however good the main font is. The icons live in the Private Use Area, which carries no Unicode meaning for macOS's fallback chain to resolve, so the lookup ends at Last Resort's box rather than finding the Nerd Font sitting right there. Turn the option off: a Nerd Font already contains the Powerline glyphs it was once needed for. ./bin/iterm-tune names both fonts and says which one is doing it.
  • Configuring Neovim — a normal run does it. If ~/.config/nvim looks untouched, the run either filtered Neovim out with --only / --skip or was given --without-nvim-config; ./bin/nvim-land reports what is missing and --apply installs it.
  • Re-runs — safe at any time. Installed tools show as existing and shell configuration is never added twice.

What changed

New: a thumbnail above the tree while you move through it. Landing on a picture or a video in the explorer — with j and k, or one click — swaps the outline pane above for a thumbnail and the numbers, and moving onto anything else, or leaving the tree, brings the outline back. Nothing reaches the editor pane until <CR> or a double click chooses the file: a picture then opens there, drawn from its full copy, and a video goes to the system's player. gx hands either to the system viewer. It is built for moving fast: the thumbnail is a small cached copy, a burst of movement asks only once the cursor rests, and a thumbnail that finishes after the cursor has moved on is discarded rather than drawn, so holding j through a folder of photos ends on the last one. The outline pane had to be told it may hold the thumbnail at all — the layout's rule that only the outline belongs there would otherwise have handed it to the editor pane on every keypress, which is the opposite of the point.

New: HEIC, TIFF, SVG, camera raw and forty-odd more open as pictures — and the ones that already did now actually show up. "Some pictures show nothing" turned out to be several bugs, found by running image.nvim's own pipeline over a corpus of real files: a PNG with transparency drew as a near-blank because sixel has no alpha; an animated PNG likewise; every frame of a GIF was stacked into one image; an animated WebP was measured as 8960×0 and so never drawn; a multi-page TIFF was identified as tifftifftiff; and a 7000×5000 PNG took over a second to encode on every redraw. Pictures now go through picture.lua, which draws one normalised copy — first frame, auto-oriented, transparency blended onto the editor's background, shrunk to at most 1600 pixels — cached by path, modification time and size. ImageMagick decodes; sips on macOS and ffmpeg take over when it cannot. Animated and multi-page files say how many frames they have, and gx hands them to the system viewer to play. Two bugs came out of testing it in a real terminal rather than headless. The second picture of each extension in a session opened as binary, because the read callback ended in return true — which in a Lua autocmd deletes the autocmd — and the video preview had carried the same line since it shipped, so the second .mp4 of a session was bytes too. And the conversion ran inside vim.system's exit callback, where vim.fn is refused, so in real use it died and left the buffer reading reading… for good.

Fix: the root picker walks instead of closing. Choosing a folder used to close the window, so reaching anything two levels away took a reopen per level. Now choosing ↓ walks into that folder and ↑ .. walks up, and the list redraws in place for as many steps as it takes; the root changes only on ✓ use this folder or Ctrl-Y. Each step clears the filter and puts the cursor back on ✓, so arriving somewhere and pressing Enter again is how you say here. Two bugs in the first version came out of testing it in a real terminal rather than headless. Its key, <C-r>, never worked: neo-tree binds that to clear_clipboard, and neo-tree resets its buffer mappings on render, so a binding made from outside was overwritten — the check that let it ship asked only whether something was mapped to the key. The key is O now, bound through neo-tree's own mapping table. And the button disappeared after its first use: it was appended to neo-tree's text, neo-tree truncates a line from the right, and the explorer pane is a fifth of the screen, so a root a few folders deep pushed it off the end. The path now gives way from the left instead — …/share/nvim/lua ▲ 󰥨.

New: a button that moves the file tree somewhere else. The explorer pane's first line is the root itself, and it now carries a folder-with-a-magnifier after the sort arrow. Press it — or, since the fix above, O anywhere in the tree — and a floating list offers everywhere the tree could be rooted instead: every directory above the current one, then the directories inside it, up and down in one prompt, because somewhere else is the question and which direction it is in is not. <BS> and . still walk one step at a time. Three details are load-bearing. The icon is declared once and read by both the renderer and the click, because a second copy is how a button appears and pressing it does nothing. The click finds the icon in the rendered line rather than counting columns, since everything before it on that line is neo-tree's — an indent, a folder icon, the root name, and a sort arrow that is only there at position current — so arithmetic would break the first time one of them changed width. And re-rooting makes the tree window current again first: the pane is neo-tree at position current, the picker is a float, and without that step the editor pane becomes a second tree.

New: completion as you type. blink.cmp is in the pinned set, so a landed box has a completion menu that appears as you type and previews the top match as grey text ahead of the cursor — candidates from the language server, paths, snippets and the words in open buffers, ranked by a real fuzzy match rather than the first tag found. This reverses a decision the configuration had been carrying: ~/.vimrc has OmniCppComplete's block commented out with a note that its popup interfered with typing, and the answer here had been that completion stays on demand. The objection was about a popup that stole keystrokes, and that is the part that is fixed — every key driving this menu falls back to what vim does when the menu is closed, <C-x><C-o> included. Four editing plugins came with it: <C-a> and <C-x> on a date, a bool and a semver rather than only an integer, :IncRename with every call site changing as you type, and [ / ] motions for a diagnostic, an indent level and the jumplist — four of those targets switched off because ]c is the git hunks and ]q and ]t are Neovim's own. Copilot's suggestion is the one entry that cannot simply land, so only its automatic trigger is gated: a box without credentials never loads it and never fetches its server, while :Copilot auth still works, because lazy refuses to load a spec whose cond is false even through its own command. The pinned set grew from 14 to 19.

Fix: iterm-tune can read a profile at all. Everything the report said about a profile — the transparency, blur, ligature and scrollback rows, and the font advisory that exists to explain a prompt full of boxes — had never once printed, on any machine. PlistBuddy splits its command on whitespace, so Print :New Bookmarks:0:Guid asks for an entry called :New and finds nothing; every per-profile key in iTerm2's preferences sits under a name with a space in it. The profile count came back 0, the report stopped after the three global rows, and --apply wrote none of the per-profile settings while reporting each one as done. The same shape as duti -x in the VLC script: the tool answers, the answer means nothing was found, and nothing checked which. The key path is now built from segments that each carry their own quotes, so it cannot be reassembled wrong, and the test asserts the string handed to PlistBuddy — which needs no macOS to check. The font report gained the setting that had been invisible all along: iTerm2's separate non-ASCII font, which overrides the main one for every icon whenever it is on. Both fonts are still reported and never modified; they are your choice, not a performance knob.

New: a picture leaves for its own viewer too. <CR> or a double click on a .png, .jpg, .jpeg, .gif, .webp, .avif or .bmp hands it to whatever the system opens pictures with, exactly as a video goes to VLC. A single click still previews it in the editor pane. The reason is the same on both sides: sixel in a pane a third of the screen wide is a thumbnail, not a look at the image, and a video buffer draws one frame because 24 fps of sixel is 14 MB/s of escape sequences. The preview is the boundary, not a shortfall of it. The two extension lists now live in lua/hikovim/media.lua and three readers share them — video.lua's BufReadCmd, image.nvim's hijack_file_patterns, and the tree. image.nvim exposes no accessor for what it was told to hijack, so a second copy is exactly how a format would end up with a preview and no viewer.

New: choose a video and it plays. <CR> or a double click hands the file to vim.ui.open, which is open on macOS and xdg-open on a Linux desktop, so it goes to whatever owns the type; on a machine that has run bin/vlc-default that is VLC. Both are bound because both mean I have chosen this one; a single click means show me this one and still previews — a frame and the numbers, in the editor pane. A directory still expands and every other file still opens in the editor pane, so neither key is taken away from them. A box with no desktop to hand a file to says so and points at mpv --vo=tct rather than going quiet. The editor names no player of its own: that binding belongs to the system, and saying it in two places is how the two come apart. The buffer still plays nothing, which is the same boundary as before — one 960×540 frame is 625 KB of sixel, so 24 fps would be 14 MB/s of escape sequences with the statusline tearing through every one. Playback belongs to a player, and this is the shortest way to hand it over.

One detail there is load-bearing rather than cosmetic: the click that previews a video leaves the cursor in the tree. A mouse mapping is looked up in the buffer that is current when the key is processed, and the first click of a double click used to open the preview and jump to the editor pane — where <2-LeftMouse> is not mapped, so the second click reached nothing and the double click did nothing at all. Reading neo-tree's state the wrong way hid the other half: at position current that state is held per window, and asking for the tab's answered an empty one, so every single click fell through to <CR> instead.

Fix: the picture stays in the editor pane. Clicking an image in the tree sometimes drew it over the tree as well, on top of the file names. neo-tree sits in the explorer pane at position current, which is what makes it render into a window the layout built rather than opening a sidebar of its own — and its own open reads that literally: for current it skips the window search altogether and opens the file in the window it is already in. So every file opened from the tree appeared in the explorer pane first, and the layout moved it to the editor a turn of the loop later. Invisible for text. Not for an image: image.nvim hijacks on BufWinEnter, so it bound a picture to the explorer window and began drawing there, and by the time it finished the buffer had gone — its renderer bails out of a window that no longer shows the buffer without clearing what it already painted, and a sixel is painted on the terminal rather than owned by a buffer. The image stayed on the tree, in both panes at once, and only sometimes, because which of the two won the race decided it. neo-tree announces an open before it performs one, so the layout answers that and puts the file in the editor pane itself; S, s and t still split and open tabs, and with the layout off neo-tree's own logic is still in charge.

New: VLC opens video files, not QuickTime. bin/vlc-default is the third companion script, and the first about the machine rather than the terminal: macOS hands .mp4 and .mov to QuickTime Player, which cannot play a good half of what a real collection holds. It points 24 video content types at VLC — between them .mp4 .m4v .mkv .avi .mov .qt .wmv .flv .f4v .webm .mpg .mpeg .m2v .ts .m2ts .mts .vob .3gp .3g2 .asf .rm .rmvb .divx .ogv .ogm .mxf .dv — reports by default, backs up before writing and undoes with --restore. Content types rather than extensions, so an extension a later VLC adds to a type it already claims comes along for free; audio, images and playlists keep whatever owns them now. The bundle identifier is the point: a Parallels virtual machine publishes its Windows applications as genuine .app bundles, so a machine running VLC inside Windows has two of them and the Windows one can win .mp4 — a double click then boots a virtual machine to watch a file. This writes org.videolan.vlc and nothing else, and names any second VLC it finds without touching it. duti -x mp4 is not a check either: it resolves by application name and will name the Parallels one when the binding is correct, so the report reads the LaunchServices preference file and --apply re-reads it afterwards rather than trusting duti's exit status.

New: a video shows a frame, not binary. Opening an .mp4 used to fill the window with rubbish. Now you get what yazi shows for the same file — one frame taken a tenth of the way in, plus resolution, codec, frame rate, duration, size and bitrate — from the ffprobe and ffmpeg already in the catalog, so it costs no new dependency. Both run asynchronously and a missing one costs only that half of the preview. The buffer is nowrite, so :w can never put the preview text where the video was. It deliberately plays nothing: one 960×540 frame is 625 KB of sixel, so 24 fps would be 14 MB/s of escape sequences for the terminal to parse, and a sixel image is painted on the terminal rather than owned by a buffer, so every statusline tick would tear through it. Hand a video to open, or to mpv --vo=tct over SSH.

New: images in the editor pane. Click a .png in the tree and the picture appears where the file contents would, the way yazi previews one. The backend is the whole story: every Neovim image plugin draws with the Kitty graphics protocol, which iTerm2 does not speak — it has its own inline-images protocol, which is why yazi can show an image in iTerm2 and these plugins cannot. What iTerm2 does speak is sixel, and sixel is image.nvim's third backend, so that is what this uses, with the ImageMagick nanolander already installs. On a terminal that speaks the Kitty protocol — Ghostty, Kitty, WezTerm — one line changes and it gets faster. lazy.nvim's LuaRocks support is turned off alongside it, because image.nvim's rockspec would otherwise have lazy bootstrap a Python-and-compiler build on a box whose whole point is that it just lands.

New: a file tree, and no more nested Neovim. nvim <file> typed in the terminal pane used to start a second Neovim inside the pane — a separate process, so nothing in ide.lua could see it, let alone move the file to the editor pane. Both halves of the fix ship: flatten.nvim catches any nested Neovim in that pane, including a git commit that has to block, and a one-line shell function covers what you type on machines that only got the shell config. Both key off $NVIM, which Neovim exports inside its own :terminal. Separately, the explorer pane is now a hierarchical tree: oil shows one directory at a time on purpose, so neo-tree.nvim navigates in the pane while oil still edits and still answers <F5>. The pinned set grew from 9 to 13 — neo-tree brings plenary.nvim and nui.nvim with it. Also fixed: ./bin/nvim-land --freeze could never add a plugin, because its guard counted lazy-lock.json as unapplied drift when rewriting that file is exactly what --freeze is for.

The toolkit grew from 19 to 54, with install paths verified on all four operating systems and every supported architecture. The script itself now passes ShellCheck.

Fix: a run installs the whole catalog, not one tool. A run used to stop after the first tool it actually installed, and report success. The catalog was fed into the install loop on standard input, and the commands in that loop read standard input too — dnf reads it to ask whether to import a repository GPG key. That one install consumed every remaining catalog line, the loop ran out of input, and the summary was honest about what it had reached: each of those tools really had passed. Nothing said the other forty-seven were never attempted. The visible effect was a machine that filled up one tool per run; an Amazon Linux 2023 box took six runs to reach seven of the fifty-four, each time reporting All requested tools passed verification. The catalog now arrives on file descriptor 3, which no installer touches, and standard input stays on your terminal so a package manager that must ask you something still can.

Fix: a tool is verified only if it says its version. ~/.local/bin/fastfetch turned out to be a bash-completion script: the release tarball carries two files called fastfetch, and the search for the payload took whichever the filesystem listed first, which is not the same order on every machine. Verification then ran it, and sourcing a completion script exits 0 and prints nothing. Both halves are fixed, because either alone still lets a broken install through — the payload search prefers an executable file, and verification requires the version query to print something on either stream.

Fix: a tool that cannot run here is a skip, not a failure. Amazon Linux 2023 is on glibc 2.34, and tree-sitter, resvg, and Neovide publish Linux binaries wanting 2.39 or 2.35: each installed correctly and was then refused by the loader. Those report SKIPPED (platform) with the glibc version named, and the unusable binary is removed rather than left on PATH. gping is pinned to its static musl build for the same reason yazi is, so it works there now. entr and ncdu, which Amazon Linux packages and upstream both lack, are skips too — while a package install that ran and failed stays a FAILED row, so a broken apt is never reported as a quiet skip. A complete run on Amazon Linux 2023 exits 0 again instead of 2. Two smaller fixes came from the same run: Neovide publishes an uncompressed .tar, which was not on the list of archive extensions, so the tarball itself was installed as the binary; and filtered tools and platform gaps shared one counter, so a run with no filter could report Skipped by filter: 5.

New: yazi and its preview backends. yazi joins the catalog as the file manager, with the six things it hands a file to when it cannot render it itself: file, FFmpeg, Poppler, 7-Zip, ImageMagick, and resvg. Two mechanisms came with them. github_asset_name pins the exact release asset for the two projects where keyword matching picks the wrong file — yazi's gnu build, which will not run on Amazon Linux 2, and FFmpeg's -gpl-shared build, whose binary needs a lib directory the install discards. github_extras installs the second binary an archive carries when it is not optional: ya with yazi, ffprobe with FFmpeg. make_compat_links gained two more links for the reason it had the first two: older p7zip packages call 7-Zip 7z, and ImageMagick 6 has convert but no magick.

nanolander

帶著整套裝備降落在任何一台機器上

快速開始

下載後直接執行即可，腳本會自行判斷平台與架構。

# 安裝全部工具
$ git clone https://github.com/hikohong/nanolander.git
$ cd nanolander
$ ./bin/nanolander

# 完成後啟用設定（Ubuntu 用 ~/.bashrc）
$ source ~/.zshrc

命令列選項

全部可以組合使用，例如 --set-default-shell --with-aliases --configure-git。

--list-tools

列出腳本可安裝的所有工具與用途，先看清單再決定要不要過濾。

./bin/nanolander --list-tools
--only a,b,c

只安裝指定工具，其餘標為 SKIPPED。適合補裝少數項目，或在網路受限的機器上快速裝必要工具。指令名或工具名都可以。

./bin/nanolander --only nvim,tmux,fzf,ripgrep
--skip a,b,c

安裝全部但排除指定項目。沒有 Docker 的機器可以排除 lazydocker 與 dive。

./bin/nanolander --skip lazydocker,dive
--set-default-shell

在 macOS 與 Amazon Linux 上把登入 shell 改成 zsh，已經是 zsh 就不動作。Ubuntu 使用 bash 設定，此選項不生效。

--with-aliases

加入可選別名區塊：ls ll lt 導向 eza、cat 導向 bat、du 導向 dust、df 導向 duf、top 導向 btm。每行都先確認工具存在才生效，區塊有起訖標記，隨時可整段刪除。

--configure-git

把 git-delta 設為全域 Git 分頁器，git diff、git log、git show 都有語法高亮與行號；同時把合併衝突樣式設為 zdiff3。git 或 delta 不存在時會警告並略過。

--help

顯示使用說明與範例，不安裝任何東西。

運作方式

每項工具都跑同一條流程，安裝來源與驗證結果都會記錄在摘要中。

環境偵測

以 uname -s 與 /etc/os-release 判斷系統，決定套件管理器與 shell 設定目標，並把 uname -m 正規化為 x86_64／arm64／armv7／armv6，作為挑選 Release 檔案的依據。

wants_tool

--only 與 --skip 的過濾判斷，忽略大小寫與空白，指令名或工具名皆可命中。被過濾的項目標為 SKIPPED，不算失敗。

setup_homebrew

macOS 專用。找不到 brew 時下載官方安裝程式並以非互動模式執行，接著載入對應的 brew shellenv。

install_package 系列

把「套件庫有沒有」「本機裝了沒」「執行安裝」三件事包成統一介面，內部依平台切換 apt-cache／dpkg-query／rpm／brew。try_package_candidates 再依序嘗試不同發行版的套件名，例如 fd-find 與 fd、tlrc 與 tldr。

github_install

套件庫沒有的工具走這裡：查最新 Release、依架構挑檔、驗證 SHA-256、解壓後安裝到 ~/.local/bin。挑檔時先比對完整結尾再退回關鍵字包含，避免 linux_arm 誤選到 linux_arm64；壓縮檔內檔名不同的專案（yq）會自動改名，直接發佈單一執行檔的專案（shfmt、direnv）則略過解壓縮；Neovim 保留完整 runtime 目錄並建立連結。設定 GITHUB_TOKEN 可提高 API 額度。

make_compat_links

Ubuntu／Debian 的執行檔叫 fdfind 與 batcat，這裡建立 fd 與 bat 連結，讓各平台用法一致。

command_works

不只看指令存不存在，而是實際執行版本查詢（tmux 用 -V、unzip 用 -v、其餘 --version；entr 沒有版本參數，以存在於 PATH 為準），通過才記為成功。

日誌與回傳狀態

每次執行都會產生與畫面完全相同的日誌：~/nanolander-YYYYMMDD-HHMMSS.log。安裝失敗時，可用工具名稱搜尋對應區段，例如 == Installing yq ==。

注意事項

  • sudo 密碼：Linux 安裝系統套件時可能要求輸入密碼，腳本開頭會先驗證 sudo 權限。
  • GitHub API 限制：未登入額度較低，一次安裝多項工具可能出現 403。先 export GITHUB_TOKEN=… 再執行即可。
  • Docker 相關工具：lazydocker 與 dive 需要本機有可用的 Docker 才能實際運作，沒有的話用 --skip lazydocker,dive。
  • 只有套件庫來源的工具 — tig、cscope、entr、ctags 沒有官方跨平台執行檔，只能靠發行版套件庫。Amazon Linux 2023 未內建 EPEL，這幾項可能標為 FAILED，可用 --skip tig,cscope,entr 排除。
  • Amazon Linux 2：套件庫較舊，多數現代工具會改用 GitHub Release 安裝到 ~/.local/bin，屬正常行為。
  • armv6 機器：官方 Release 支援有限，沒有對應版本的工具會標為 FAILED，可用 --only 指定確定可用的項目。
  • 重複執行：可安全重跑，已安裝的顯示 existing，shell 設定也不會重複加入。
